# Research & Discovery: Multi-Layer AI Code Indexing (AST $\rightarrow$ IR $\rightarrow$ Machine Code)

**Workspace Artifact:** `research.md`  
**Target Environment:** Google Antigravity IDE / CLI (`/plan` & `/goal` Discovery Phase)  
**Scope:** End-to-end multi-representation code intelligence index unifying syntactic trees, cross-file semantic graphs, compiler SSA intermediate representations, and disassembled binary control-flow graphs.

---

## 1. Problem Statement & Motivation

Standard AI code assistants rely on single-layer lexical chunking or shallow Abstract Syntax Tree (AST) splitting paired with dense text embeddings. While effective for surface-level autocomplete and docstring lookup, single-layer AST indexing fails on four critical engineering tasks:

1. **Implicit Control and Data Flow:** High-level syntax obscures how values propagate across branches, pointer aliases, and loop-carried dependencies.
2. **Compiler Lowering & Optimization Blindness:** Semantically identical routines written in different styles (e.g., an `if-else` clamp vs. a ternary expression) produce distinct AST subtrees, whereas an optimizing compiler lowers both into identical branchless instructions (`select` in LLVM IR and `cmovg` in x86-64).
3. **Cross-Language Equivalence:** Polyglot repositories binding Rust, C++, and Python via FFI cannot unify execution semantics at the syntax layer alone, but converge when lowered to LLVM Intermediate Representation (IR).
4. **Binary & Stripped Artifact Alignment:** Security auditing, firmware vulnerability detection, and profiler-guided optimization require mapping stripped machine-code basic blocks back to source-level symbols and IR graphs.

---

## 2. Four-Layer Representation Analysis

### Layer 1: Syntactic Layer (AST / CST)
* **Parser Engine:** `tree-sitter` (incremental GLR parsing supporting 100+ languages with error recovery for incomplete edits in the IDE).
* **Chunking Strategy (cAST):** Recursive AST traversal that splits large files along cohesive syntactic nodes (`function_definition`, `impl_item`, `class_specifier`) while prepending a **Scope Header** containing enclosing namespace, class, and import declarations.
* **Extracted Features:**
  * Node kind, byte span $[b_{\text{start}}, b_{\text{end}}]$, line span $[l_{\text{start}}, l_{\text{end}}]$.
  * Cyclomatic complexity estimate $M = E - N + 2P$ computed over syntactic branch tokens.
  * Raw identifier tokens split by `camelCase` and `snake_case` for trigram lexical indexing.

### Layer 2: Cross-File Semantic & Code Property Graph (SCIP / CPG)
* **Protocol:** SCIP (Sourcegraph Code Intelligence Protocol) generated by `scip-clang`, `rust-analyzer`, and `scip-python`.
* **Unified Graph Structure:** Merges the AST with inter-procedural Call Graphs (CG), Type Hierarchy Graphs (THG), and intraprocedural Data Flow Graphs (DFG).
* **Canonical Symbol URI Format:**
  $$\text{SymbolID} = \langle \text{scheme} \rangle : \langle \text{package} \rangle / \langle \text{version} \rangle / \langle \text{descriptor\_chain} \rangle$$
* **Key Value for Antigravity Agents:** Enables deterministic 1-hop and $k$-hop caller/callee impact analysis before an agent modifies a shared interface.

### Layer 3: Compiler Intermediate Representation (LLVM SSA IR)
* **Extraction Mechanism:** Intercept build targets via `compile_commands.json` or `rustc --emit=llvm-bc` and invoke Clang/LLVM with `-O1 -gline-tables-only -emit-llvm` to normalize syntactic sugar while preserving DWARF source-line mappings (`!dbg`).
* **Graph Formulation (ProGraML Topology):**
  Let the IR graph be a directed multigraph $G_{\text{IR}} = (V, E, \tau_V, \tau_E)$ where:
  * $V = V_{\text{inst}} \cup V_{\text{val}} \cup V_{\text{type}}$ represents instructions, SSA values/constants, and types.
  * $E = E_{\text{ctrl}} \cup E_{\text{data}} \cup E_{\text{call}}$ captures control transfer, SSA def-use edges, and call sites.
  * Positional edge encoding $p(e) \in \mathbb{N}$ distinguishes operand order (e.g., dividend vs. divisor in `sdiv`).

### Layer 4: Disassembled Machine Code & Binary CFG
* **Lifting & Disassembly:** `LIEF` for ELF/Mach-O/PE section parsing combined with `Capstone` for instruction decoding (`x86-64` and `AArch64`).
* **Instruction Canonicalization (OOV Mitigation):**
  Raw assembly suffers from out-of-vocabulary (OOV) explosion due to arbitrary memory offsets and immediate constants. Every decoded instruction $I = (\text{opcode}, \text{op}_1, \dots, \text{op}_k)$ is normalized via a deterministic mapping $\Phi(I)$:
  * General-purpose registers map to width-preserved canonical classes (`rax`, `eax` $\rightarrow$ `REG64_RET`, `REG32_RET`).
  * PC-relative jump targets map to `<BB_TARGET>`.
  * Memory displacements `[rbp - 0x18]` map to `[REG_FP - DISP_LOCAL]`.
  * Immediate constants above a threshold $|c| > 256$ map to `<IMM_CONST>`.
* **Cross-Layer Alignment:** The `.debug_line` DWARF state machine maps machine instruction virtual addresses $\text{VA} \in [\text{VA}_{\text{low}}, \text{VA}_{\text{high}})$ back to `(file_id, line, column)`, linking binary basic blocks directly to Layer 1 AST nodes and Layer 3 LLVM IR instructions.

## 3. Tri-Modal Storage & Hybrid Retrieval Formulation

To serve low-latency queries inside Antigravity via the Model Context Protocol (MCP), the index coordinates three storage engines linked by a shared `ChunkUUID`:

| Storage Modality | Engine | Indexed Artifacts | Query Pattern |
| :--- | :--- | :--- | :--- |
| **Lexical & Trigram** | Tantivy | Source tokens, normalized IR opcodes, canonical assembly strings | Exact identifier, regex, instruction sequence search |
| **Dense Vector** | Qdrant | AST code embeddings ($d = 768$) + IR/Binary GNN embeddings ($d = 256$) | Natural language RAG, semantic clone detection |
| **Property Graph** | Memgraph / SQLite-Graph | SCIP symbol edges, CPG def-use chains, LLVM CFG/DFG, DWARF links | Multi-hop impact analysis, taint & data-flow slicing |

### Reciprocal Rank Fusion (RRF) Across Modalities
When an Antigravity agent issues a hybrid query $q$, candidate code units $u \in \mathcal{U}$ are scored across active retrieval modalities $m \in \{\text{lex}, \text{ast\_vec}, \text{ir\_gnn}, \text{bin\_cfg}, \text{graph}\}$ using weighted Reciprocal Rank Fusion:

$$\text{Score}_{\text{RRF}}(u, q) = \sum_{m \in \mathcal{M}} \frac{w_m}{\eta + \text{rank}_m(u, q)}$$

where $\eta = 60$ dampens outlier ranks and $w_m \in [0, 1]$ is dynamically routed based on query intent (e.g., increasing $w_{\text{ir\_gnn}}$ and $w_{\text{bin\_cfg}}$ for optimization or binary similarity queries).
